# ADR-0010: CI/CD

## Context

ROMAS Wire has 6 deployable surfaces (4 Workers + 2 Pages projects) + a Supabase database. CI must run G1–G10 quality gates on every PR. CD must deploy preview environments per PR and prod on main merge.

## Decision

- **CI**: GitHub Actions runs on every PR + main push
  - G1 Lint (ESLint + Prettier, `--max-warnings=0`)
  - G2 Typecheck (`tsc --noEmit --strict`)
  - G3 Test (Vitest unit + integration; Playwright E2E on PR; pgTAP via `supabase test db`)
  - G4 Build (`turbo run build --filter=*`)
  - G5 Security (`pnpm audit --audit-level=high` + `semgrep ci` + `gitleaks detect`)
  - G6 No-TODOs scan in changed files
  - G7 No-secrets scan (`gitleaks` again, hard-fail on any)
  - G8 Device test (Playwright launches preview deploy + screenshots key surfaces)
  - G9 Schema tests (pgTAP runs against fresh DB seeded with migrations + seed.sql)
  - G10 RSS lint (xmllint against atom 1.0 + iTunes/podcast namespace; custom embargo lint on `conference-brief.xml`)
- **CD**:
  - Preview: `wrangler pages deploy --branch=<branch>` + Supabase branch DB per PR
  - Production: on merge to `main`, deploy in order: migrations → Workers → Pages
  - Atomic deploys per surface; rollback via `wrangler rollback` and `wrangler pages deployment rollback`

**Cloud auth**: GitHub Actions OIDC → Cloudflare API token (short-lived) where Cloudflare supports OIDC; fallback to repository-secret short-lived API token rotated 90d. Supabase CLI uses repository-secret access token.

## Alternatives considered

| Option | Rejection reason |
|---|---|
| **Cloudflare Workers Builds (native)** | Newer, less ecosystem support, no PR-comment annotations from GitHub. GitHub Actions is the lingua franca. |
| **Buildkite / CircleCI** | Cost + complexity for a 1-person org without payoff over GitHub Actions. |
| **Render / Railway / Fly** | Wrong substrate; the SSOT locks Cloudflare. |
| **Branch-deploy-everything-on-every-PR** | Cost: Supabase branch DBs are charged per environment; cap at 10 active preview branches via auto-cleanup. |
| **Manual deploy** | Defeats the purpose; one human step is one opportunity for inviolable-rule violation. |

## Consequences

**Positive**:
- GitHub Actions has first-class OIDC for short-lived cloud credentials (no long-lived keys in repo)
- Per-PR preview deploys give Kimal a clickable URL for review before merge
- Atomic surface deploys mean a single Worker bug doesn't block the rest
- Forward-only migration policy: any rollback is a new corrective migration, never destructive

**Negative**:
- 6 deployable surfaces = 6 workflows; complexity managed by `reusable-workflows.yml` pattern
- Supabase branch DBs cost ~$0.01/hour per branch — capped via auto-prune after 7 days

**Neutral**:
- Release tagging: `releases/YYYY-MM-DD` annotation in Sentry for error attribution

## Workflow files (planned)

```
.github/workflows/
  ci.yml                  # lint, typecheck, test, build on every PR
  deploy-preview.yml      # per-PR preview deploy
  deploy-production.yml   # main merge → prod (sequential: migrations → workers → pages)
  reusable-build.yml      # shared steps
  reusable-deploy-worker.yml
  reusable-deploy-pages.yml
  release-tag.yml         # manual workflow_dispatch to tag a release in Sentry
```

## Rollback procedures

- **Reader/CMS**: `wrangler pages deployment rollback --project=<>`
- **Workers**: `wrangler rollback`
- **DB**: forward-only. Corrective migration adds the fix; never `DROP` a previously-applied change without an ADR.
- **Audio (post-publish)**: revoke kill switch (60s SLA, watchdog enforced) — not a deploy rollback but the user-facing equivalent.

## Revisit triggers

- GitHub Actions monthly minutes cost > $50
- Cloudflare introduces OIDC + first-class Workers builds with better DX
- Supabase branch DB billing model changes
- Any deploy that takes >10 minutes p99 (currently target ~5 min for full stack)
